# 独立静态站主展示层候选：讨论记录与暂缓决定

## 当前状态

- 记录日期：2026-08-11。
- 状态：`deferred`。
- 当前决定：保留方向与恢复入口，暂不制作 POC，不选择框架，不部署站点。
- 人类决策点：只有 Lee 后续明确提出扩展展示层，才重新开启方案比较与验证。

## 讨论背景

P8 文章 Review 期间，临时 HTML 预览采用统一的正文宽度、中文排版、章节层级、表格、引用块、代码块和配图样式。该预览已经完成桌面端与移动端浏览器检查；Lee 的直接反馈是，其阅读效果甚至优于 Wiki 对 Markdown 的默认渲染。

现有发布约定已经预留这一方向：`content/articles/<series-id>/*.md` 是唯一内容源，个人网站等展示层应由源文生成，不能反向成为源稿。参见 [`docs/publishing-workflow.md`](../publishing-workflow.md) 的“后续扩展”。

## 已确认的稳定结论

1. 值得保留的是预览页的阅读设计，不是当前临时 HTML 文件本身。
2. 如果未来建设主力展示层，应在构建阶段把 `status: ready` 的 Markdown 预渲染成静态 HTML；不为每篇文章手工维护第二份 HTML，也不依赖浏览器运行时再从仓库读取 Markdown。
3. Markdown 与 frontmatter 继续作为唯一内容源；静态站、GitHub Wiki、Gitee Wiki、墨问及其他平台仍是可重新生成的展示或分发层。
4. 独立静态站可以作为未来的主阅读入口候选；Wiki 是否降级为镜像与备用入口，要等真实站点验证后再决定。
5. 当前 `.p8-preview.html` 只是本地 Review 工具，不是已经冻结的生产模板，也不应被解释为静态站 POC 已启动。

## 尚未决定的事项

以下事项全部保持开放，不在本次讨论中提前冻结：

- 使用薄型自定义生成器，还是 Astro、Hugo 等静态站框架。
- 部署到 GitHub Pages、其他静态托管服务或自有域名。
- 首页、系列目录、全文搜索、RSS、sitemap、评论和多语言的具体范围。
- Wiki 在新展示层上线后的长期角色。
- 当前预览样式是否直接成为正式 Design System，还是只作为视觉基线。

GitHub Pages 只在讨论中作为低依赖候选出现，不构成已经作出的部署决定。

## 重新启动时的最小验证

若未来决定继续，先做一个可停止的小范围验证，而不是直接迁移全部发布链路：

1. 选择三篇代表文章：纯文字长文、多表格文章、包含图片与代码块的文章。
2. 只构建 `status: ready` 的内容，并验证 draft/review 不会进入公开输出。
3. 从统一模板生成文章页、系列目录及上一篇/下一篇导航。
4. 验证图片路径、frontmatter metadata、移动端排版、链接和发布前门禁。
5. 在一个候选托管环境中预览，不立即切换主入口。
6. 由 Lee 比较静态站、Wiki 和现有分发页面的实际阅读体验，再决定是否升级为主展示层。
