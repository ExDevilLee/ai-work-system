# macOS 正式实验报告（deepseek-v4-flash 对照）

日期：2026-08-06

## 实验配置

- 模型：`deepseek-v4-flash`。
- 推理强度：`max`。
- 执行器：`codex-cli 0.146.1`。
- 平台：macOS，Apple Silicon。
- 会话：每次使用独立 `--ephemeral` 新会话。
- 沙箱：`read-only`。
- 样本：3 个任务 × 2 个条件 × 6 次，共 36 次预定义正式运行。

本对照使用与 [`formal-macos-gpt-5.6-sol-medium.md`](formal-macos-gpt-5.6-sol-medium.md) 相同的协议与夹具（`pilot-02`）。不同模型的数据没有并入本报告的正式样本，聚合产物按模型独立命名（`data/formal-macos-deepseek-v4-flash-max.{json,csv}`）。

全部 36 次运行满足协议门禁：

- 退出码：36/36 为 0。
- 运行时工具访问（`runtime_tool_access_calls`）：36/36 为 0。

`protocol_valid` 判定全部为 `yes`。

## 可以支持的结论

在本实验中，把当前状态、稳定规则和参考资料按职责分开，可以明显减少单一任务返回给 Agent 的项目文本，同时保持答案正确性。该收益与 gpt-5.6-sol 对照一致，说明在弱推理模型（`deepseek-v4-flash` + `max`）上同样成立，且与模型强弱无关地复现。

## 不能支持的结论

### 分层不一定减少调用次数

参考资料任务中，Layered 的调用中位数（3.5）高于 Baseline（2）。索引和入口文件可能减少正文读取量，也可能增加导航步骤。

### 分层不一定更快

稳定规则、参考资料两个任务中 Layered 的耗时中位数均未低于 Baseline。延迟还受到模型服务、缓存和全局运行时行为影响，不能根据当前小样本声称分层会加速回答。

### 项目文本减少不等于计费 token 同比例减少

`workspace_output_bytes` 只测量工具返回的项目文本；input token 包含系统上下文、缓存和运行时技能，两者不能直接换算。本次 input 中位数差值远小于输出字节差值，即属此例。

### 结果不能直接推广到所有模型和项目规模

当前夹具较小，模型固定，任务答案确定。真实项目的文件数量、命名质量、入口说明和模型工具策略都会改变结果。

## 当前判断

截至 2026-08-06，macOS 正式 POC 已完成 deepseek-v4-flash(max) 对照：36 次运行全部协议有效、全部满分，分层带来的按需加载收益在两种模型上一致复现，同时也保留“不更快、参考资料任务调用更多”的反例。文章结论仍应限定为当前模型、macOS 和当前任务规模。
