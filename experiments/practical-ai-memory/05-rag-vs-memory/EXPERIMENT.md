# 实验协议

## 研究问题

在原始资料、冻结 Top-K 检索结果、任务提示和模型配置相同的前提下，检索后的行动治理方式是否会影响 Agent 对静态事实、当前有效动作、未解决冲突、适用范围和历史变化的判断？

本实验只研究“相关资料已经找回以后”的决策阶段，不评价 embedding、向量数据库、分词、召回率或 rerank 算法。

## 待验证假设

1. 静态事实任务中，三个条件都可能依靠相同检索结果正确回答。
1. `rag-only` 可能找回全部相关记录，却无法稳定判断哪条记录仍能指导当前行动。
1. `rag-with-recency` 可能处理明确替代，但可能在未解决冲突或范围差异中把“最新”误认为“当前有效”。
1. `memory-governed` 的潜在价值不是召回更多文本，而是提供当前状态、适用范围、决定来源和停止行动的边界。
1. RAG 与 Memory 可能是互补关系：前者找回证据，后者判断证据是否仍能指导当前行动。

这些都只是待验证假设。Pilot 与正式矩阵不得把条件名称直接当成评分结论，也不得预设 `memory-governed` 必须获胜。

## 实验变量

三个条件共享相同的 `corpus/`、`retrieval-packets/` 和任务提示。条件只改变检索结果进入回答前的行动治理规则。

### RAG Only：仅检索结果

Agent 获得任务对应的冻结 Top-K 证据包及其来源标签，不获得独立的当前状态投影。它可以引用、比较和解释所有片段，但没有额外规则声明哪条记录当前有效。

### RAG With Recency：检索加时间优先

Agent 获得与 `rag-only` 完全相同的证据包，并被要求在同一主题出现多条记录时优先采用时间最新的记录。该条件不维护争议、批准层级、适用范围变化或显式退出状态。

### Memory Governed：检索加当前记忆治理

Agent 获得相同证据包，并读取 `memory/CURRENT.md` 中的当前状态投影。只有 `active` 且范围匹配的内容可以指导当前行动；冲突待决、历史记录和已经退出的结论仍可用于解释与审计，但不能直接成为当前指令。

`CURRENT.md` 只保存状态、适用范围、当前动作和决定来源，不复制原始资料正文。需要解释依据时仍应回到冻结检索包中的原始证据。

## 冻结检索与 BM25 核验

正式矩阵不实时运行检索器。每个任务使用一份提前冻结的 Top-K 证据包，确保三个条件面对完全相同的资料、顺序和字节内容。

夹具验证必须检查：

- 每个任务只有一份共享检索包，条件目录不得保存副本。
- 检索包 manifest 记录来源相对路径、顺序、UTF-8 字节数和 SHA256。
- 检索包中的正文必须逐字来自 `corpus/`，不得补写答案或状态标签。
- Prompt 只能引用任务 ID，不得暴露条件名称、预期答案或评分项。

Pilot 前使用 Python 标准库 SQLite FTS5 的 `bm25()` 对共享语料执行一次召回核验。每个任务冻结包中的必要来源都必须进入约定 Top-K；否则先修订查询或语料，不得启动模型。

BM25 核验只证明冻结证据能够由普通全文检索得到，不进入三组正确性、耗时、调用或上下文指标，也不支持对真实 RAG 产品的召回质量结论。

│   ├── references/

│   └── decisions/
├── retrieval-packets/

│   └── <task-id>.md

运行时为每个条件创建独立临时工作区，只复制共享冻结检索包和当前条件文件。原始 `corpus/` 只用于 Pilot 前的包内容与 BM25 核验，不进入模型工作区。运行器不得读取真实记忆目录或用户级 Codex 插件。

## 测试任务

每个任务使用独立新会话，避免前一任务的读取内容进入后一任务。

| 任务 | 主要验证目标 | 理想结果 | 满分 |
| --- | --- | --- | ---: |
| `static-reference` | RAG 擅长的稳定事实检索 | 正确列出固定检查项并给出来源 | 4 |
| `approved-decision` | 讨论与正式决定同时命中时的当前动作 | 采用已批准决定，不把讨论意见当指令 | 6 |
| `unresolved-conflict` | 两组相反证据尚未解决 | 不静默选边，提出控制变量后的复验 | 6 |
| `scope-bound-rule` | 新记录只适用于部分平台或项目 | 按范围给出动作，不向其他范围泛化 | 6 |
| `historical-trace` | 当前动作与历史变化同时追溯 | 说明当前动作、旧结论退出原因和对应来源 | 6 |

每个条件单轮满分 28 分；3 次重复后每个条件满分 84 分。正式矩阵三个条件合计满分 252 分。

## 冻结评分结构

逐任务 rubric 从以下维度中选择明确评分项，合计分数必须与上表一致：

- **事实命中**：回答是否包含问题所需事实。
- **当前动作**：是否给出此刻唯一且正确的行动，或在不能行动时明确暂停。
- **状态判断**：是否区分当前有效、历史、冲突待决和已经退出的内容。
- **范围约束**：是否避免把局部记录扩大为全局规则。
- **来源追溯**：当前动作与历史解释是否引用实际使用的来源。
- **安全边界**：是否存在无依据断言、静默选边或执行失效规则。

评分遵循以下公平性约束：

- 静态事实任务中三组使用相同评分表，任何条件都可以满分。
- `rag-only` 找回全部记录时应获得对应事实与来源分，不能仅因缺少状态文件而整题记零分。
- `rag-with-recency` 在明确替代场景中可以满分；只有时间规则导致实际错误时才扣分。
- `memory-governed` 必须实际给出正确动作、状态、范围和来源，不能因条件设计而自动得分。
- `protocol_valid`、无依据断言和无关项目事实独立记录，不用机制预期代替逐份 Review。

在查看 Pilot 答案前完成 `expected/answers.json` 和 `expected/rubric.json`。正式矩阵开始后不得修改预期答案、评分项或分值。

## 指标

### 正确性与行动治理

- 每个任务的 rubric 得分。
- 找回事实但给出错误当前动作的次数。
- 未解决冲突被静默选边的次数。
- 范围错误泛化次数。
- 已退出记录继续指导行动的次数。
- 当前动作与历史来源追溯完整度。

### 上下文与执行

- `resident_instruction_bytes`：根目录 `AGENTS.md` 的 UTF-8 字节数。
- `workspace_output_bytes`：可可靠识别的工作区工具输出字节数。
- `project_context_bytes`：上述两项之和，只在指标覆盖完整时使用。
- 工作区调用次数、耗时、input tokens、output tokens 和 reasoning tokens。

过程指标只用于描述机制成本。由于操作系统沙箱、命令重试和 Agent 工具选择会影响读取路径，不用这些指标单独判断机制质量或 OS 性能。

### 人工成本

Pilot 只记录协议 Review 是否可以依据冻结 rubric 完成。正式评分前启动真实计时，记录批次大小、总分钟数和每次均摊方式；缺少真实时间时不得估算或补造。

## 隔离、隐私与元数据

- 所有内容使用合成项目、平台和发布记录。
- 不包含真实用户、账号、凭据、存储地址、设备路径、会话标识或私有项目内容。
- 运行器使用独立临时目录、临时会话、UTF-8 stdin，并显式关闭用户级插件。
- `runtime_tool_access_calls` 必须为 0，工作区指标覆盖必须完整且输出可靠。
- 模型名称、推理强度、Codex CLI 和平台标签写入 metadata；不记录或公开模型 provider。
- 私有 `raw.jsonl`、`final.md`、`stderr.log` 和 `score.json` 不进入公开仓库。
- 模型生成的临时绝对路径链接只能保留在私有运行区；公开分析只使用相对来源标签。

## Pilot 矩阵

Pilot 为 `5 个任务 x 3 个条件 x 1 次`，共 15 次。条件顺序按任务轮换，降低固定执行顺序影响。Pilot 只验证协议，不进入文章数据。

Pilot 开始前固定记录：

- 模型：`gpt-5.6-sol`。
- 推理强度：`medium`。
- Pilot 启动时实际使用的 Codex CLI 版本。
- 夹具、Prompt、检索包 manifest、预期答案和 rubric 哈希。

出现以下任一情况时立即停止并修订：

- 冻结检索包无法通过 corpus 内容、顺序、字节数或 SHA256 校验。
- BM25 核验不能把必要来源召回约定 Top-K。
- 条件间共享证据、Prompt 或任务事实不等价。
- Prompt 泄漏条件名称、文件路径、预期答案或评分项。
- 自动注入的 `AGENTS.md` 未被实际加载。
- MCP 或命令读取无法完整分类和计量。
- 运行访问隔离夹具以外的文件、真实记忆或用户级插件。
- Prompt 截断、编码异常、退出码非零或四类运行文件不完整。
- Pilot 中三个条件没有形成可解释的行为差异。
- 冻结 rubric 无法公平评价某个条件，或必须看到答案后新增评分项。
- 模型、推理强度或 CLI 在同一批次内发生变化。

Pilot 完成后先逐份只读语义 Review。只有证据等价性、运行隔离、指标覆盖、评分可执行性和条件可区分性同时通过，才冻结正式矩阵。

## Pilot 01 结果

macOS Pilot 01 已按 `5 个任务 x 3 个条件 x 1 次` 完成 15 次运行。运行层结果全部有效：

- 15/15 退出码为 0，运行文件完整。
- 15/15 使用 `gpt-5.6-sol`、`medium` 和 Codex CLI `0.145.0`。
- 15/15 关闭插件，没有运行时越界访问。
- 15/15 工作区指标覆盖完整且输出可靠。
- 每个任务的三个条件使用同一个 Prompt 哈希；每个条件的 fixture 哈希在五个任务中保持一致。
- 未创建 `score.json`，未启动正式矩阵。

只读语义 Review 显示 15 份答案均可按当前 rubric 满分。静态事实任务符合预期，但四类行动任务也没有形成条件差异。当前冻结检索包直接包含了“正式决定”“冲突待解决”“范围决定”和“旧做法退出”等状态答案，使 `rag-only` 与 `rag-with-recency` 无需独立状态投影也能正确判断当前行动。

这触发了协议中的“条件不可区分”停止门禁。Pilot 01 只证明运行链路健康，不支持任何机制优劣结论。修订必须在重新运行 Pilot 前完成，且不得复用本批答案作为新协议证据。

下一版夹具应保持研究主轴与三组共享原始证据不变，但调整状态信息的承载位置：

- 把未获批准的讨论记录放在已批准决定之后，避免时间顺序恰好等同于批准顺序。
- 原始检索包只保留观察、决定正文、日期和来源 ID，不直接写入“当前”“退出”“冲突待解决”等汇总答案。
- `memory-governed` 的状态投影负责维护批准层级、争议状态、适用范围和退出关系，正文解释仍回到共享检索包。
- 保留静态参考任务作为公平性对照，三个条件仍应都能满分。
- 修订后重新冻结 manifest、Prompt、预期答案和 rubric，并重新执行 15 次 Pilot。

详细 Review 记录见 [`analysis/pilot-01.md`](analysis/pilot-01.md)。

Pilot 02 将状态结论从共享检索包移入独立状态投影，成功形成批准层级和范围关系差异，但历史任务缺少 rubric 要求的平台相关状态证据，因此仍未通过。Pilot 03 增加共享技术观察 OBS-503 后重新执行全部 15 次运行，最终通过门禁。

Pilot 03 的只读建议总分为：

- `rag-only`：26/28。
- `rag-with-recency`：23/28。
- `memory-governed`：28/28。

这组分数只验证 rubric 可执行性，不进入文章结果。协议允许检索条件在证据足够时满分，也允许 `memory-governed` 因未实际满足评分项而扣分；条件名称本身不产生分数。

正式矩阵冻结候选使用当前 `pilot-02` fixture set、现有 Prompt、预期答案与 rubric。完整 Review 见 [`analysis/pilot-02.md`](analysis/pilot-02.md) 和 [`analysis/pilot-03.md`](analysis/pilot-03.md)。

## 正式矩阵候选

Pilot 通过后，macOS 与 Win11 分别完成 `5 个任务 x 3 个条件 x 3 次`，每个平台 45 次，共 90 次正式运行。运行期间未修改模型、推理强度、CLI、夹具、Prompt、检索包、预期答案和 rubric。

两个平台的条件总分一致：`rag-only` 为 `75/84`，`rag-with-recency` 为 `69/84`，`memory-governed` 为 `84/84`。15 个分组中有两个 `rag-with-recency` 分组存在平台差异：Win11 在已批准决定上比 macOS 低 3 分，在范围限定规则上高 3 分；其余 13 个分组一致。完整对照见 [`analysis/formal-macos-win11-comparison.md`](analysis/formal-macos-win11-comparison.md)。

矩阵中断恢复只允许跳过满足全部门禁的成功运行。失败或不完整运行必须整体隔离，保留原因和哈希后使用相同槽位重跑，不得以手工修改运行产物绕过失败。

## 文章主题与结论边界

推荐标题：

> RAG 能把资料找回来，为什么还不等于系统形成了长期记忆？

文章只有在正式证据支持时，才讨论“RAG 找证据、Memory 治理当前行动”的互补关系。文章不得声称：

- 所有 RAG 系统都没有状态治理能力。
- 向量数据库不能实现长期记忆。
- 当前 POC 测量了 embedding、rerank 或召回算法优劣。
- 一份 `CURRENT.md` 能解决真实项目的全部记忆问题。

候选参考来源在实现阶段建立独立 literature ledger，并在写作前逐项验证：

- Lewis et al. 的 Retrieval-Augmented Generation 原始论文，用于界定检索增强生成。
- Cognitive Architectures for Language Agents，用于梳理 Agent 记忆模块与行动循环。
- MemGPT 原始论文，用于比较分层上下文与外部记忆管理思路。

候选来源只用于后续核验，不代表当前协议已经采用其中全部主张。

## 有效性限制

- 冻结检索包隔离了召回波动，因此不能评价真实检索器端到端效果。
- SQLite FTS5/BM25 核验只覆盖当前小型合成语料和查询。
- 小型文件夹夹具不能代表大型知识库、并发写入或多人治理成本。
- `rag-only`、`rag-with-recency` 和 `memory-governed` 是可解释对照，不代表所有产品实现。
- 每个组合 3 次重复不足以形成稳定的耗时或 token 排名。
- 当前实验验证读取时的行动判断，不验证记忆写入、晋升、生命周期变更或物理删除。
