稳定参考、未解决冲突和历史追溯在三种条件下都能正确回答。这说明检索包已经明确包含状态语义时，额外状态投影不一定改变答案。

主要差异出现在“相关记录都找到了，但仅凭正文仍不能确定当前动作”的任务：

- `rag-only` 在三次已批准决定任务中有一次拒绝选择当前方案；三次范围任务都无法确认 Blog-B 与 Note-C 已退出 PNG 强制范围。
- `rag-with-recency` 三次都让日期较新的增量更新 proposal 指导行动，取消了正式方案要求的全量重建和发布后远端检查。
- `memory-governed` 通过 `active`、`proposed`、`retired`、适用范围和当前动作投影，15 个组合全部命中冻结 rubric。

## 当前可以支持的结论

1. 正确检索到相关资料，不保证能够从互相冲突或状态不明的记录中恢复唯一当前动作。
2. 时间排序可以帮助定位较新记录，但不能替代批准状态、冲突状态和适用范围。
3. 当证据包本身已经明确表达“冲突待解决”或历史退出原因时，单独的当前状态投影未必带来额外正确性收益。
4. 当前记忆治理层的核心作用不是再次保存全文，而是投影哪些记录仍能指导行动。
5. RAG 与长期记忆不是互斥替代关系：检索负责找回相关证据，记忆治理负责把证据转换为当前可执行状态。

## 有效性限制

- 每个任务与条件只有 3 次重复，不支持稳定的耗时或 token 排名。
- 使用合成夹具，尚未覆盖真实项目中的大规模语料、增量索引和多人修改。
- Review 未盲化条件名称，45 次采用一次真实计时后的批量均摊方式。
- 正式矩阵冻结了相同 Top-K 检索包，只验证检索后的行动治理，不评价 embedding、rerank 或召回质量。
- 本报告只覆盖当前模型、推理强度、CLI 和 macOS 工具链；Win11 尚未复现。
