## 根因

冻结检索包不只提供原始事实，也直接给出了治理结论：

- `approved-decision` 中正式决定比讨论记录更新，时间优先刚好得到正确答案。
- `unresolved-conflict` 包含明确的“当前没有批准统一等待时间”和“冲突待解决”。
- `scope-bound-rule` 包含明确的正式范围决定，三组都能直接判断 Wiki-A、Blog-B 和 Note-C。
- `historical-trace` 包含明确的“不再指导当前迁移”和“只保留为历史记录”。

模型无需读取独立状态投影，也能从共享包中完成批准层级、争议状态、范围和退出关系判断。因而本轮主要测到了文本理解能力，没有有效隔离行动治理机制。

## 修订方向

下一版仍应保持三组面对同一份原始证据，不转向评测召回算法。需要修改的是状态信息的表达层：

1. 让时间与批准层级脱钩。例如先有正式决定，后有未批准的新讨论，使 `rag-with-recency` 不能依靠日期偶然正确。
2. 从原始证据中移除直接给答案的状态汇总句。观察和决定保留日期、内容与来源 ID，但“当前有效、争议、退出”由治理层维护。
3. 让范围变化包含跨范围继承风险，而不是由最新决定直接列出所有平台答案。
4. 保留历史正文，但将当前替代关系放入状态投影，检验“可追溯”与“仍可行动”的区别。
5. 保留 `static-reference` 不变，继续验证治理层不会损害普通资料检索。

修订后必须重新运行 fixture validator、BM25 核验、全部单元测试和 15 次 Pilot。当前 Pilot 不得并入新批次，也不得启动正式 45 次矩阵。
