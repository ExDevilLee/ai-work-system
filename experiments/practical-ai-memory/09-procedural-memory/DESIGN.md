# 第 9 篇 POC 设计：程序性记忆

## 研究问题

当同类任务重复出现时，AI 是否应该继续依赖临时提示词，还是可以把经过验证的做法沉淀为 Guide、Skill 或工作流？本 POC 只研究“可复用行为契约”是否减少重复成本，不研究某个 Skill 产品的通用优劣。

## 对照条件

| 条件 | Agent 可见材料 | 要回答的问题 |
| --- | --- | --- |
| `prompt-only` | 任务说明、合成项目文件 | 每次临时说明能否完成任务 |
| `guide-assisted` | 上述材料 + 只读 Guide | Guide 是否减少重复说明并保持边界 |
| `skill-workflow` | 上述材料 + 版本化 Skill/工作流入口 | 稳定程序性记忆是否减少返工且不越权 |

三种条件共享同一批任务和输入，不共享运行输出、评分或其他条件的隐藏状态。

## 任务族

1. `classify-change`：根据变更类型选择已有处理路径，不新增规则。
2. `prepare-review`：生成最小 Review 清单，保留未知项和人工门。
3. `apply-scope`：只在声明的项目/平台范围内应用规则。
4. `recover-failure`：遇到失败时按停止、回滚、人工确认顺序处理。
5. `distill-candidate`：从三次重复结果中提出候选规则，但不自动晋升。

每个任务至少准备三个语义等价但表述不同的输入变体，避免把单一模板记忆误判为可复用能力。

## 指标与门禁

主指标：任务正确率、越权/越范围次数、返工次数、人工 Review 是否通过。

过程指标：重复说明量、读取工作区字节数、工具调用次数、端到端耗时。过程指标只作量级参考，不单独代表质量或生产率。

程序性记忆只有在以下条件同时满足时才进入候选：

- 至少三个语义等价变体均完成；
- 没有越权、静默扩大范围或跳过人工门；
- 失败路径仍能停止并留下来源；
- 结果相对 `prompt-only` 的改进不是由泄漏答案、额外上下文或任务变简单造成；
- 由人工 Review 决定是否晋升为候选 Guide/Skill，而不是由评分器自动写回。

## 非目标与风险

- 不证明 Skill 对所有模型、团队或生产任务都有效。
- 不比较外部平台的 Skill 数量或采用率。
- 不使用真实仓库规则、真实用户资料、账号、密钥、会话 ID 或本机绝对路径。
- 公开材料不得包含真实密钥或真实会话 ID。
- 如果 `skill-workflow` 出现越权，即使正确率更高，也判为协议失败。

## 验证边界

初始 Pilot 采用 macOS 两个请求配置，每配置 45 格。正式矩阵换用 `formal-01` 新任务表，每配置
`5 个任务 × 3 个条件 × 3 个变体 × 3 轮 = 135` 格，三轮轮换条件顺序。两种配置独立统计；
正式结果为 224/270，其中 45 格为批次 JSON 结构失败，1 格为禁止自动晋升字段失真。不安排
Win11，也不把条件通过率解释为载体优劣。
