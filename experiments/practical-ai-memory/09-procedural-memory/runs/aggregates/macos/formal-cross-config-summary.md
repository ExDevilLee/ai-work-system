# P9 双配置正式矩阵汇总

## 总结果

两个 macOS 请求配置共完成 270 格正式矩阵，最终为 **224/270 通过**。

| 请求配置 | 通过 | 总数 | 批次结构失败 | 单格契约失败 |
| --- | ---: | ---: | ---: | ---: |
| `gpt-5.6-terra / medium` | 120 | 135 | 15 | 0 |
| `deepseek-v4-flash / max` | 104 | 135 | 30 | 1 |
| 合计 | 224 | 270 | 45 | 1 |

45 个结构失败来自 3 个 15 格批次：多余逗号、JSON 字符串内未转义控制字符，以及 code fence 加
未转义引号。另有 1 格把“不自动晋升”误写为“不自动晋缘”，未通过关键契约。失败样本均保留，
没有通过手工修 JSON、重跑覆盖或文字纠错变成通过。

## 按条件汇总

| 条件 | 通过 | 总数 |
| --- | ---: | ---: |
| `prompt-only` | 60 | 90 |
| `guide-assisted` | 75 | 90 |
| `skill-workflow` | 89 | 90 |

这组差异不能证明载体优劣：失败主要由批次级 JSON 结构决定，一次结构失败会同时影响 15 格；两组
请求配置还使用不同执行路径与推理强度。更稳妥的结论是，程序性边界在 225 个可独立解析的格中
有 224 格通过，但结构化合批本身是正式矩阵暴露出的可靠性风险。

- rubric 只扩展等价的安全表达；没有降低“JSON 可解析、15 格齐全、禁止自动晋升”等硬门禁。
