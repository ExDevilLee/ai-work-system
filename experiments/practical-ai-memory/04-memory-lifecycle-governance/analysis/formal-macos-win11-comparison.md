# macOS 与 Win11 正式矩阵对照

## 对照范围

两个平台使用相同冻结夹具、提示、评分表和模型配置：

- 每个平台 45 次正式运行，共 90 次。
- 模型：`gpt-5.6-sol`。
- 推理强度：`medium`。
- Codex CLI：`0.145.0`。
- 三个条件：`append-only`、`latest-wins`、`lifecycle-governed`。
- 每个任务与条件：`n=3`，`workspace_metrics_n=3`。

数据入口：

- [`formal-macos-gpt-5.6-sol-medium.json`](../data/formal-macos-gpt-5.6-sol-medium.json)
- [`formal-win11-gpt-5.6-sol-medium.json`](../data/formal-win11-gpt-5.6-sol-medium.json)

Win11 只回传脱敏聚合文件。私有原始事件、最终答案、评分文件、本机路径和会话标识仍保留在 Windows 设备。

## 跨平台一致与不同

两个平台共同复现了相同的治理语义：

1. 只追加能保留冲突和历史，却不能让明确被替代、范围收窄或紧急撤销的旧规则退出当前行动。
1. 最新记录优先能低成本处理明确替代，却会在未解决冲突中把时间顺序误当成证据结论。
1. 生命周期治理在本轮五类任务中同时保留历史和维持唯一当前动作。
1. 预设有效期在三种条件下都能让临时规则自然退出。

平台差异主要出现在执行过程，而不是正确性：

- Win11 的 45 次正式运行都需要从 PowerShell 沙箱拒绝中恢复。
- 恢复读取已经进入工作区指标，45/45 的覆盖完整且输出可靠。
- 两个平台的过程成本不同，因此不把调用、字节或耗时差异解释成治理机制本身的跨平台性能差异。

## 结论边界

本轮结果支持：在冻结的合成夹具、当前模型、推理强度和 CLI 下，生命周期治理相对只追加和最新记录优先的正确性方向可以在 macOS 与 Win11 独立复现。

本轮结果不能证明：

- 所有 Windows 环境、模型、CLI 或 Agent 工具都会得到相同结果。
- 五个合成任务覆盖真实长期记忆的全部冲突和恢复路径。
- `84/84` 代表生命周期治理没有维护、并发或人工决策成本。
- 两个平台的调用、输出字节和耗时可以直接用于操作系统性能比较。
