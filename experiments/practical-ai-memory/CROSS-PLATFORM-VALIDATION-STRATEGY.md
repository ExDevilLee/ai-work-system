# 第二系列 POC 验证策略：macOS 双模型对比

## 目标

本策略用于决定“AI 长期记忆实战”系列 POC 如何检验治理结论是否只属于某一个模型配置。

从第六个 POC（`06-current-memory-map`）起，系列不再在 Win11 上重复完整正式矩阵，改为在 macOS 上用两个定位不同的模型配置互为对照：

- 强力配置：`gpt-5.6-sol`，推理强度 `medium`。
- 快速配置：`deepseek-v4-flash`，推理强度 `max`。

两个配置使用同一套冻结夹具、提示和评分表，只改变模型与推理强度，聚合数据按模型独立命名。这样既能检验治理结论是否跨模型成立，又不必把“双平台完整矩阵”当成每篇文章的固定仪式。

## 默认方案：macOS 双模型完整矩阵

适用于后续所有 POC。

要求：

- 在 macOS 上为每个模型配置各完成一次 Pilot、正式矩阵、真实计时 Review、评分和聚合。
- 两个配置的正式矩阵规模一致（相同任务数、条件数和重复次数），便于百分比口径对照。
- 文章只能声明“已在 macOS 上用两个模型配置实测”。
- 过程指标（耗时、token、工具调用）受 Codex CLI 版本、缓存和服务波动影响，只能作量级参考，不能直接归因于模型本身。

## 何时仍需要 Win11 验证

默认不安排 Win11 验证。只有当研究问题直接依赖操作系统行为时才单独考虑：

- 研究变量是文件系统、路径、换行、编码、Shell、进程启动、权限或索引可移植性。
- 主题涉及记忆备份、恢复、跨平台同步或跨设备协作，操作系统本身属于实验变量。
- macOS 结果出现无法解释的工具链差异，需要排除平台因素。

即使安排，也只做兼容性 Smoke（每任务每条件各一次），不等于正确性已经完成跨平台独立复现。

## 方案编写要求

每个新 POC 的 `EXPERIMENT.md` 应在正式运行前记录：

- 两个模型配置各自的模型、推理强度和 Codex CLI 版本。
- macOS 正式矩阵的样本规模（两个配置规模一致）。
- 是否安排 Win11 验证及触发依据（默认不安排）。
- 文章允许使用的声明口径。
- 不记录或公开模型 provider。

## 历史背景：第一至第五个 POC 的跨平台验证

本系列的验证策略经历过一次调整：

- 第一至第五个 POC（01 至 05）采用“macOS 主体 + Win11 分级验证”策略：macOS 完成完整正式矩阵，Win11 按 Level 2 执行 15 次兼容性 Smoke 或按 Level 3 执行完整矩阵。这一阶段的双平台验证对实验基础设施很有价值，也发现了 EOL、路径排序、沙箱拒绝等问题。
- 从第六个 POC 起，第三至第五个 POC 的主要治理语义跨平台方向已经稳定，每篇机械复制完整双平台矩阵的边际收益下降；系列改为 macOS 双模型对比，把验证资源投向“治理结论是否跨模型成立”。

01 至 05 的既有数据继续保留，不受本策略调整影响。
