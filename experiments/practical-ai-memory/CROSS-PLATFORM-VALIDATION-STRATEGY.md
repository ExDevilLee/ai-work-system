# 第二系列跨平台 POC 验证策略

## 目标

本策略用于决定“AI 长期记忆实战”后续 POC 是否需要在 macOS 与原生 Win11 上重复完整正式矩阵。

默认不把“双平台完整矩阵”当成每篇文章的固定仪式。macOS 继续作为主体实验平台；Win11 根据研究问题、工具链风险和声明强度采用分级验证。

## 默认分级

### Level 1：macOS 主体实验

适用于研究变量主要是文本语义、状态治理、晋升规则、Review 边界或人工决策，不直接依赖操作系统行为的 POC。

要求：

- 在 macOS 完成 Pilot、正式矩阵、真实计时 Review、评分和聚合。
- 文章只能声明“已在 macOS 实测”。
- 不把实现层面的理论可移植性写成 Win11 实测结果。

### Level 2：macOS 完整矩阵 + Win11 兼容性 Smoke

这是后续 POC 的默认方案。

要求：

- macOS 完成完整主体实验。
- Win11 执行仓库同步、EOL、CLI、模型、登录、帮助参数、静态测试、夹具和隐私门禁。
- Win11 对全部任务与条件各运行一次。例如 5 个任务与 3 个条件执行 15 次 Smoke。
- 每次 Smoke 都检查文件完整性、插件关闭、隔离环境、MCP 分类、指标覆盖和语义回答。
- Smoke 失败立即停止，不自动替换失败槽位，不进入正式矩阵。

通过后只能声明“Win11 兼容性 Smoke 通过”。这不等于正确性已经完成跨平台独立复现。

### Level 3：macOS + Win11 完整正式矩阵

满足以下任一条件时升级到完整双平台验证：

- 研究问题直接涉及文件系统、路径、换行、编码、Shell、进程启动、权限或索引可移植性。
- 结论依赖按需读取是否成功、工具调用次数、输出字节或恢复路径。
- 主题涉及记忆备份、恢复、跨平台同步或跨设备协作，操作系统本身属于实验变量。
- Win11 Smoke 与 macOS 出现语义方向差异、协议异常或无法解释的工具链差异。
- macOS 结果接近评分边界，少量波动可能改变文章主要结论。
- 文章准备明确声明“已在 macOS 与 Win11 独立复现”。
- 共享运行器、Codex CLI、模型、隔离方式或指标审计器发生可能影响平台行为的变更。

完整矩阵必须使用相同冻结夹具、提示、评分表、模型配置和停止门禁。两个平台的过程指标不能直接解释为操作系统性能差异。

## 周期性回归

即使连续 POC 都只需要 Level 2，也应在以下时间点安排一次 Level 3 回归：

- 每完成 2 至 3 个新 POC。
- 共享实验运行器或 MCP 指标分类器发生实质变化。
- Codex CLI 或主体模型升级。
- Win11 长时间未验证，环境和工具链可能已经漂移。

周期性回归可以选择最能覆盖文件读取、状态判断和隔离门禁的代表性 POC，不要求把所有历史 POC 全部重跑。

## 方案编写要求

每个新 POC 的 `EXPERIMENT.md` 应在正式运行前记录：

- 当前采用的验证级别及选择依据。
- macOS 和 Win11 各自需要执行的样本规模。
- Win11 从 Smoke 升级为完整矩阵的触发条件。
- 文章允许使用的平台声明。
- 模型、推理强度和 Codex CLI；不记录或公开模型 provider。

生成 Win11 提示词时必须先引用本策略，再结合当前 POC 的任务数、条件数、冻结 fixture、运行器参数和隐私边界生成具体步骤，不能直接复制旧 POC 的命令。

## 既有五个 POC 的经验

- 第一篇的 Win11 验证发现 EOL、路径排序、启动器、编码、stdin 和 MCP 指标问题，证明早期完整双平台验证对实验基础设施很有价值。
- 第二篇的按需读取受到 Windows 沙箱拒绝和重试影响，平台工具链直接影响研究变量，完整双平台矩阵是必要的。
- 第三至第五篇的主要治理语义跨平台方向稳定，平台差异更多体现在读取路径、过程指标和少数回答细节，说明每篇机械复制完整矩阵的边际收益已经下降。

因此后续默认采用 Level 2，并根据明确触发条件升级到 Level 3。
